CASE STUDY 03 · 데스크탑 대시보드 · B2B

가게장부

복잡한 통계 대신, 오늘 무엇을 채워야 할지 알려주는 장부

역할
1인 기획·리서치·UI 디자인
기간
개인 프로젝트 · 약 3주
도구
Figma, HTML/CSS 목업
유형
실무 아님 · 개인 연습 프로젝트
정직 고지. 실제 자영업자와의 라포 형성이 어려워 가상 인터뷰 시나리오로 대체했습니다. 실제 서비스화 시에는 최소 5인 이상의 실제 사장님 인터뷰가 선행되어야 합니다.
01 · PROBLEM

배달앱, POS, 재고관리 — 앱 3개를 오가는 사장님

영세 소상공인은 배달앱 정산, POS 매출, 재고관리를 각각 다른 화면에서 확인해야 합니다. 디지털전환 과정에서 이런 "정보 파편화"를 겪는다는 문제의식은 소상공인 대상 조사에서도 비슷한 맥락으로 확인됩니다 — 중소기업중앙회가 소상공인 500개사를 대상으로 실시한 조사(2026.6.9 발표)에서도 소상공인 10곳 중 8곳이 디지털·AI 기술을 활용하고 있지만 상당수는 배달앱과 POS, 키오스크 등 기초 단계에 머물러 있다는 취지의 결과가 나왔습니다. 다만 "정보 파편화"라는 표현 자체를 명시한 1차 출처는 찾지 못해, 이 문장은 위 조사 결과로 뒷받침되는 추론이라는 점을 밝힙니다(출처 확인 필요).

80%
  • 디지털·AI 기술 활용 80%
  • 미활용 20%

모바일 앱 2개와 달리, 이 프로젝트는 데스크탑/태블릿 대시보드 형태로 설계해 포트폴리오에 다른 UI 패턴(표, 카드, 데이터 시각화)을 더하는 것을 의도했습니다.

02 · RESEARCH

리서치 방법과 한계

  • 공공기관 자료 인용 — 소상공인 디지털전환 실태 관련 공공 자료 확인
  • 가상 인터뷰 시나리오 — 실제 라포 형성이 어려워, 공개 자료를 바탕으로 가상의 인터뷰 시나리오를 구성 (실제 인터뷰 아님 — 명시)

가상 인터뷰 시나리오 초안은 생성형 AI로 여러 버전을 뽑아본 뒤, 공공기관 통계자료와 어긋나는 내용은 걸러내고 방향성이 맞는 부분만 참고했습니다. 시나리오 자체를 실제 데이터로 취급하지 않았습니다.

페르소나

영자 (52) · 동네 분식집 사장님

스마트폰 사용은 익숙하지만 엑셀·통계 화면은 부담스러워함. 장사 중에는 화면을 오래 들여다볼 여유가 없음.

03 · SOLUTION

핵심 화면

Figma 없이 HTML/CSS로 직접 구현한 코드 목업입니다. 실기기 스크린샷이 아닌 구조·정보위계 전달용 목업이며, 화면 안의 수치(매출·재고 등)는 시연용 예시 데이터임을 밝힙니다.

1
절대값 대신 방향성

"132만원" 같은 숫자 대신 "어제보다 좋음/나쁨" 방향성 중심으로 표현해, 통계에 익숙하지 않은 사용자의 인지 부담을 줄였습니다.

2
정보 밀도 축소

데스크탑 대시보드는 정보를 많이 넣기 쉽지만, "사장님이 하루 1번, 30초 안에 확인할 정보"로 기준을 좁혀 카드 3개로 제한했습니다.

3
추천 근거 표기

"떡 5kg 발주 추천"이라는 결과만 보여주지 않고 "최근 7일 평균 소진량 기준"이라는 근거를 병기해 신뢰를 확보했습니다.

04 · DESIGN DECISIONS

왜 이렇게 결정했는가

  • 절대값 대신 방향성. "132만원" 같은 숫자 대신 "어제보다 좋음/나쁨" 방향성 중심으로 표현해, 통계에 익숙하지 않은 사용자의 인지 부담을 줄였습니다.
  • 정보 밀도 축소. 데스크탑 대시보드는 정보를 많이 넣기 쉽지만, "사장님이 하루 1번, 30초 안에 확인할 정보"로 기준을 좁혀 카드 3개로 제한했습니다.
  • 추천 근거 표기. "떡 5kg 발주 추천"이라는 결과만 보여주지 않고 "최근 7일 평균 소진량 기준"이라는 근거를 병기해 신뢰를 확보했습니다.

고려했지만 기각한 대안

매출·재고 데이터를 그래프와 표로 상세히 보여주는 정통 BI 대시보드 형태도 검토했습니다. 더 많은 정보를 한 화면에 담을 수 있다는 장점이 있었지만, 페르소나(영자 사장님)가 "엑셀·통계 화면은 부담스러워함"이라고 리서치에서 확인된 만큼, 상세 분석 기능을 앞세우면 오히려 핵심 사용자층을 소외시킬 수 있다고 판단해 기각했습니다. 대신 "오늘 무엇을 확인해야 하는지"만 압축한 카드 3개 중심 구조를 유지하고, 상세 데이터는 필요한 사람만 별도로 찾아볼 수 있게 최소한만 노출했습니다.

05 · RESULT

결과 (정성적)

2인정성적 관찰(실제 UT 아님) — 자영업 경험자 대상 더미 데이터 리뷰
1건 개선정성적 관찰(실제 UT 아님) — "발주 추천 기준이 불투명하다" 피드백 → 근거 텍스트 추가
카드 3개정성적 관찰(실제 UT 아님) — 정보량을 핵심 지표로 압축
06 · RETROSPECTIVE

회고

실제 POS·배달앱 API 연동 없이 더미 데이터로 진행했다는 한계가 있습니다. 발주 추천 로직도 복잡한 예측 모델이 아닌 단순 임계값 기반이라는 점을 밝힙니다. 다음 단계로는 실제 사장님 인터뷰를 통해 "임계값을 어떻게 설정할지"에 대한 실제 니즈를 확인하고 싶습니다.
